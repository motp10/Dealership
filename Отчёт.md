## Доменная область

Приложение представляет собой информационную систему автосалона. Оно позволяет создавать автомобили из набора деталей, рассчитывать их стоимость, а также оформлять заказы на покупку, тест-драйв и комплектацию автомобиля.

## Стек реализации

- Java 21
- Spring Boot
- Spring Web и Spring Validation
- Spring Data JPA / Hibernate
- PostgreSQL
- Liquibase для миграций базы данных
- Gradle для сборки
- Docker и Docker Compose
- Swagger / OpenAPI для документирования API
- JUnit и Testcontainers для тестирования

## Основные сущности доменной области

- **Car** — автомобиль с брендом, моделью, базовой стоимостью и выбранными деталями.
- **Detail** — деталь автомобиля: кузов, цвет, топливо, трансмиссия, привод, колёса и другие компоненты.
- **User** — пользователь системы с ролью администратора или клиента.
- **ConfigurationOrder** — заказ автомобиля с выбранной комплектацией.
- **OrderStockCar** — заказ уже существующего автомобиля.
- **TestDriveOrder** — заявка на тест-драйв.
- **Status** — состояния заказов: создан, подтверждён, оплачен, закрыт или отменён.

## 12 Факторов

1 В проекте используется одна кодовая база сервиса, хранящаяся в одном репозитории git

2 Все зависимости проекта объявлены в файле build.gradle

3 Основная конфигурация запуска хранится в .env.example и задаётся через переменные окружения

4 Сервис БД является подключаемым ресурсом, поднимается в отдельном docker контейнере и может быть запущен отдельно

5 В build.gradle созданы отдельные задачи для сборки, запуска и управления приложением 

6 Процессы приложения запускаются в отдельных контейнерах, а данные хранятся в отдельной базе данных, которая не привязана к процессу приложения и фронтенду

7 В контейнерах приложения открыты порты для взаимодействия с клиентом

8 Сервис, БД и фронтенд запускаются в разных контейнерах, в будующем для горизонтального масштабирования можно будет добавить новые контейнеры

9 Реализованы задачи DockerUp, DockerDown и DockerDownV для удобного запуска и остановки приложения. Приостановке приложения контейнеру дается 30 секунд для корректного завершения stop_grace_period: 30s

10 Для локального запуска и запуска в контейнере используются одинаковые зависимости и версии Java, PostgreSQL. Необходимые задачи описаны в одном файле build.gradle

11 Логирование настроено через Spring Boot. Уровень логирования задаётся через переменную окружения logging.level.root=${LOG_LEVEL:INFO} и пишется в stdout/stderr

12 Задачи миграции базы данных и запуска приложения разделены
