## Доменная область

Приложение представляет собой информационную систему автосалона. Оно позволяет создавать автомобили из набора деталей, рассчитывать их стоимость, а также оформлять заказы на покупку, тест-драйв и комплектацию автомобиля.

## Стек реализации

- Java 21
- Spring Boot
- Spring Web и Spring Validation
- Spring Data JPA / Hibernate
- PostgreSQL
- Liquibase для миграций базы данных
- Gradle для сборки
- Docker и Docker Compose
- Swagger / OpenAPI для документирования API
- JUnit и Testcontainers для тестирования

## Основные сущности доменной области

- **Car** — автомобиль с брендом, моделью, базовой стоимостью и выбранными деталями.
- **Detail** — деталь автомобиля: кузов, цвет, топливо, трансмиссия, привод, колёса и другие компоненты.
- **User** — пользователь системы с ролью администратора или клиента.
- **ConfigurationOrder** — заказ автомобиля с выбранной комплектацией.
- **OrderStockCar** — заказ уже существующего автомобиля.
- **TestDriveOrder** — заявка на тест-драйв.
- **Status** — состояния заказов: создан, подтверждён, оплачен, закрыт или отменён.

## 12 Факторов

1 Вся кодовая база сервиса лежит в одном репозитории git

2 Все зависимоти объявлены в файле build.gradle

3 Вся конфигурация хранится в .env.example

4 Сервис БД является подключаемым ресурсом, поднимается в отдельном докер контейнере, может быть запущен отдельно

5 В build.gradle созданы отдельные таски для сборки и запуска приложения

6 

7 В контейнере приложения открыт порт для взаимодействия с клиентом 

8 Сервис и ДБ поднимаются в разных контейнерах, для горизонтального масштабирования несложно добавить новые. Все данные хранятся в stateless процессе БД.

9 Реализованы таски DockerUp DockerDown DockerDownV для удобного запуска и остановки приложения

10 Для локального запуска и запуска в контейнере используются одинаковые зависимости и версии java, PostgreSQL. Таски прописаны в одном gradle.build.

11 Логи приложения собираются с помощью SpringBoot. Уровень логирования указан в application.properties через переменную окружения logging.level.root=${LOG_LEVEL:INFO}

12 Задачи миграций и старта приложения разделены
