# Auto Dealership — Microservices System

Информационная система автосалона, построенная на основе микросервисной архитектуры с использованием Spring Boot. Проект реализует управление автомобилями, складскими остатками, заказами и конфигурацией автомобилей, а также синхронное и асинхронное взаимодействие между сервисами.

Система развернута в Kubernetes-кластере и оснащена инфраструктурой мониторинга, централизованного логирования и алертинга.

## Архитектура

Основные компоненты системы:

| Компонент | Назначение |
|---|---|
| OrderService | Управление заказами и предоставление REST API |
| StorageService | Управление складскими остатками автомобилей |
| Keycloak | Аутентификация и авторизация пользователей |
| Message Broker | Асинхронное взаимодействие между микросервисами |

Каждый бизнес-микросервис использует собственную базу данных PostgreSQL, что обеспечивает независимость хранения данных.

## Функциональность

### Бизнес-логика

- Управление автомобилями и складскими остатками.
- Оформление и обработка заказов.
- Конфигурирование автомобилей.
- Реализация бизнес-правил автосалона.

### Межсервисное взаимодействие

В системе используются два механизма взаимодействия:

- **gRPC** — синхронное получение актуальной информации о наличии автомобилей.
- **Message Broker** — асинхронный обмен событиями между микросервисами.

Для обеспечения надежной публикации событий реализован паттерн **Transactional Outbox**, позволяющий сохранять бизнес-изменения и соответствующие события в рамках одной транзакции базы данных.

### Работа с данными

- PostgreSQL в качестве основной системы хранения данных.
- Отдельная база данных для каждого бизнес-микросервиса.
- Миграции схемы базы данных для управления изменениями структуры и версионирования.
- Использование Transactional Outbox для надежной передачи событий между сервисами.

## Безопасность

Аутентификация и авторизация реализованы с использованием Spring Security и Keycloak.

Используется ролевая модель доступа (RBAC).

Доступ к просмотру автомобилей разрешен следующим ролям:

- `USER`
- `MANAGER`
- `ADMIN`

## Инфраструктура и мониторинг

Проект развернут в Kubernetes-кластере.

Инфраструктура обеспечивает:

- Оркестрацию и управление контейнерами.
- Управление конфигурацией приложений.
- Сетевое взаимодействие между микросервисами.
- Контроль состояния сервисов.
- Возможность масштабирования.

Для реализации системы наблюдаемости (Observability) используются:

- **SLF4J** — логирование событий и ошибок приложений.
- **Micrometer** — инструментирование приложений и сбор метрик производительности.
- **VictoriaMetrics** — хранение и обработка метрик.
- **VictoriaLogs** — централизованное хранение и поиск логов.
- **Vector** — сбор, обработка и доставка логов в VictoriaLogs.
- **Alerting** — оповещение о сбоях, недоступности сервисов и отклонениях от заданных пороговых значений метрик.

## Тестирование

Реализуются интеграционные тесты для проверки:

- Работы gRPC Server в `StorageService`.
- Работы gRPC Client в `OrderService`.
- REST endpoints получения автомобилей.
- Обработки таймаутов и недоступности сервисов.
- Обработки пустого результата.
- Разграничения доступа по ролям.

## Запуск

Для локального запуска инфраструктуры используется Docker Compose.

```bash
git clone <repository-url>
cd <project-directory>
docker compose up --build -d
```

Проверка состояния контейнеров:

```bash
docker compose ps
```

Просмотр логов:

```bash
docker compose logs -f
```

Остановка:

```bash
docker compose down
```

## Kubernetes

Приложение развернуто в Kubernetes-кластере. Управление компонентами осуществляется с помощью Kubernetes-ресурсов, включая:

- Deployment;
- Pod;
- Service;
- ConfigMap;
- Secret.

Для контроля работоспособности приложений используются механизмы проверки состояния.

## Результат

Реализована микросервисная информационная система автосалона с REST API, синхронным gRPC-взаимодействием, асинхронным обменом сообщениями и централизованной системой безопасности.

Для хранения данных используется PostgreSQL, управление изменениями структуры БД осуществляется посредством миграций. Для надежной публикации событий между микросервисами реализован паттерн Transactional Outbox.

Проект развернут в Kubernetes-кластере с подключенными централизованным логированием, сбором метрик и системой алертинга на базе SLF4J, Micrometer, VictoriaMetrics, VictoriaLogs и Vector.
